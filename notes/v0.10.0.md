# v0.10.0

新增 **SDK** 分頁（管理員）：在瀏覽器裡撰寫、檢查、模擬 New Horizons OS 的 App，然後匯出成
App Library 用的檔案。不需要安裝任何工具，也不需要先上傳到裝置才知道會不會被拒絕。

## 工具鏈改為 JavaScript

App Library 的編譯器、驗證器與模擬器由 Python 改寫為零相依的 JavaScript（`sdk/`），
同一份程式在 Node 命令列與這個分頁裡執行。Desktop 以 `scripts/sync_app_sdk.sh` 把它
複製到 `frontend/src/sdk/`；`frontend/tests/appSdkSync.test.mjs` 在兩者不一致時失敗。

- 產出的套件與已發布的 `dist/*.nha` **逐位元組相同**（數字沿用 Python `json.dumps` 的寫法）。
- 模擬器以 32 位元浮點運算，與 ESP32 一致；`peak`/`arg_max` 從 0 起算、`delta` 從節點的
  `value` 起算、事件需要 `emit_event` 權限、LED 不記為事件——全部依照 `FlowApp.cpp`。
- 驗證器現在會擋下過去「本地通過、裝置拒絕」的套件：LED 顏色不在調色盤、窗口合計超過
  128 個 float 的共用池、成本超過 1500 µs、debounce 超過 65535 ms、region 索引超過 255。
  `min_os` 改以版本比較。

## 編輯器

- CodeMirror 6，`.nhs` 語法高亮與自動完成（含已宣告的 region、signal、event）。
- 錯誤直接標在行與欄上，包括裝置在載入時才會回報的錯誤。
- 可從本機檔案或 **App Library** 開啟；從 Library 開啟的 App 會重新編譯並與已發布套件的
  sha256 比對，改過卻沒有提高版本號時會提醒（已發布版本不可改寫）。
- 草稿存在此瀏覽器的 localStorage；無法儲存時會提示。

## Build

- 依所選板型（已連線裝置的矩陣大小或預設尺寸）顯示節點數、每幀成本、窗口池與套件大小。
- 1–4 個 App 同時執行時每個 App 的可用時間。
- 編譯後的圖（每個節點對應回原始碼行）、sha256。
- 匯出 `app.nhs`/`readout.json`、`app.nha`、`meta.json`、`README.md`。

## 模擬器

- **錄製資料**：選擇裝置與錄製檔，逐幀或以 0.25–16× 播放、拖動時間軸（往回拖會從頭重算，
  debounce 與窗口狀態才正確）。熱力圖疊上 App 的 region，列出每個節點當下的值，並在編輯器
  標出觸發事件的那一行。若有 `.events.csv`，會以 `frame_seq` 對照**裝置實際記錄的事件**，
  列出只在模擬器或只在裝置上出現的事件。
- **即時裝置**：以裝置的即時串流在瀏覽器裡執行 App，不安裝到裝置。瀏覽器收到的串流上限為
  60 fps；以 `frame_seq` 計算缺漏的幀並提示，因為缺幀時 debounce 與窗口的結果會與裝置不同。
- **預算壓力**：可手動注入 `budget_load()`/`grace_left()`，測試以 `gate` 降級的 App。
- **Readout**：以所選裝置實際輪詢該 readout 的命令並渲染。

## 其他

- 後端新增 `GET /api/app-library/apps/<id>/source`（沿用 Library 的主機白名單、離線快取、
  64 KB 上限）。
- 視覺化頁面的配色抽出為 `lib/pressureColor.ts`，與模擬器共用；外觀不變。
- 支援舊版錄製檔的 `Timestamp` 欄位（v0.9 以前）。
