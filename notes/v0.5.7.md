# v0.5.7

## Fix: transport errors no longer clobber `last_status`

Gateway delivery failures (`command_delivery_timeout`, `command_expired`,
`device_not_connected_to_gateway`, …) keep `command: "status"` from the
original request. The backend treated those as status snapshots and wrote the
error envelope into `last_status`, wiping nested fields and leaving
`firmware_version` empty in the WebUI.

`_is_status_snapshot_result()` now rejects explicit transport/error results
(`status == "error"` / `ok is False` and known delivery messages). Successful
status-like results are unchanged.

Companion firmware fix: **NewHorizons OS v0.16.1** (dual UDP bind that prevented
Gateway commands from reaching the device).
