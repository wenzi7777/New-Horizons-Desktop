# v0.19.0

## 時鐘

搭配韌體 v1.12.0 的時鐘服務：ESP-NOW 裝置向 Hub 對時，WiFi 裝置優先向 Gateway 對時，連不上 Gateway 才用 NTP。

- **裝置設定頁新增「時鐘」區塊**：
  - 時鐘狀態：時間來源（Gateway／NTP／Hub／手動）、上次同步、誤差範圍、上次校正量、與這台電腦的時間差（約略值），以及 Gateway 或 Hub 是否支援授時、往返時間。
  - **立即同步**：送出 `clock_sync`，之後每秒查一次 `clock_status`，最多 10 秒，並顯示校正結果。
  - **使用這台電腦的時間**：Gateway、Hub、NTP 都連不上時的備援，以 `set_time` 帶 `force` 送出。
  - **同步設定**：Gateway／Hub 對時間隔；WiFi 模式另有備用的 NTP 伺服器與 NTP 校正間隔。
  - Gateway 或 Hub 版本太舊時會提示。
- **Hub 管理視窗**：顯示 Hub 自己的時鐘，可以立即同步。
- **CSV 匯出**：最後新增一欄 `time_ref`。`device` 表示時間戳來自裝置時鐘；`received` 表示裝置當時還沒有時間，用的是後端收到資料的時間（含網路延遲）。依欄名讀取的程式不受影響。
- **後端**：`pong` 與 `gateway_hello_ack` 新增整數欄位 `server_time_ms`，供 Hub 在連不上 NTP 時對時。
- **終端機**：
  - 新增 `clock-sync`、`clock-status`。
  - `set-time` 新增 `--force`。
  - 修正 `set-time` 把時間當數字送出、韌體一律回 `epoch_ms_required` 的問題。

## 壓力校正

- **逐顆列出無法擬合的原因**：取代原本的「圧力が足りません」，改成每顆感測器一行，例如「P31：有効 1/3 レベル — 120 kPa で飽和、43.3 kPa で無反応」，並依原因給建議（在飽和點以下加等級，或確認感測器確實受壓、基準是在沒負載時取的）。
- **標紅**：
  - 矩陣裡還不能擬合的感測器，外框標紅。
  - 選某顆感測器時，對它無效的等級（飽和、無反應）標紅並註明原因。
- **會飽和的感測器**另外列出，並標示從幾 kPa 開始飽和。韌體會讓它們的輸出停在最高有效等級，不再外推。
- **部分儲存**：只要有一顆感測器擬合成功就能儲存。儲存前會確認，未擬合的感測器輸出 0 kPa。
- 舊韌體沒有逐點資訊，會自動退回原本的提示，也仍然要全部擬合才能儲存。
