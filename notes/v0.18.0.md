# v0.18.0

**校正改成論文的擬合模型、氣壓校正流程對齊論文；經 Hub 的大回應可以重組；Studio 可以複製 AI prompt；指令執行器可以貼上指令。**

## 校正（Device Settings → 維護）

搭配韌體 v1.11.0：每個感測器用 p = a + b·√x + c·x 擬合，和論文同一套邏輯。

- **校正工作台**
  - 儲存條件改成「每個感測器都擬合成功」。畫面顯示「已擬合 N/M 個感測器」、點數不足或無法擬合的感測器。
  - 逐點校正（例如砝碼一次壓一格）照常可用，每個感測器用自己的壓力點擬合。
  - 有實測壓力的 level 會顯示「實測 x」。
  - 「進階」新增 **擬合設定**：最低擬合壓力、ADC1/ADC2 的讀出曲線 c1/c2；可以一鍵套用 AC14 的論文值。
  - 「進階」新增 **校正資料下載**：基線、所有壓力點、擬合係數輸出成一個 JSON。
  - 擷取失敗時會重新讀取校正狀態（裝置可能已經存了）；中繼錯誤顯示易懂的訊息。
- **氣壓校正流程**（照論文的 `run_sweep.py`）
  1. 自動進入維護模式並開始 session。
  2. 預載（預設 8 次，可調）：加壓到 20 kPa 保持 5 秒，排氣到 0.3 kPa 以下。
  3. 在基線取零點：擷取基線的同一個 10 秒時窗，壓力取中位數當零點 Z。
  4. 每個 level：目標 = 名目 + Z；穩定（±0.5 kPa 連 5 次，90 秒逾時照走並記錄）後保持 5 秒，擷取 10 秒；參考壓力 = 同一時窗的平均 − Z。
  5. 儲存並啟用；若有感測器無法擬合，仍保存資料但不啟用。
  - 預設壓力組合改成論文的 17 級（2–20 kPa）。
  - 每一步都等裝置回應並檢查錯誤，不再靠固定等待。
  - **安全**：中途出錯或按緊急停止時，不再直接停止氣壓控制（空壓機開著時停止可能打開進氣閥），改成回到基線並走「關空壓機 → 殘壓測試」流程。

## 經 Hub 的大回應

- Backend 新增 `result_chunks.py`：重組 Hub 轉發的分頁（`device_result_chunk`），以及不經 Gateway 直連 UDP 時的 `result_chunk`（以前超過約 1.2 KB 的回應會被丟掉）。
- 檔案頁每次讀 4 KB；log 預覽改成分段讀，最多 32 KB。

## App Studio

- 標頭新增 **AI prompt**：寫下想要的功能後，複製一份包含語言指南、op 表、限制、目標板子、範例，以及（可選）目前程式和錯誤的 prompt，貼給 ChatGPT／Claude 使用。
- 語言指南與範例由 `scripts/sync_app_sdk.sh` 從 NHOS App Library 同步（903a7e8）。
- Reference 分頁補上 readout 的 `chart`。

## 設備卡片

- 新增 **可視化** 按鈕：直接開啟可視化並打開這台設備（已開啟就不重複），會捲到並高亮它的卡片。

## 指令執行器

- builder 上方新增貼上框：貼上 CLI（`log-tail --lines 50`）或 JSON（wiki 範例），自動選好指令並填入欄位。不認得的參數會提示。
- 修正 builder 預設值與後端不一致：
  - 充電檔位改成 ultra_slow／slow／balanced／fast／extreme（原本的 `compatible` 會被拒絕）。
  - 電源狀態補上 soft_off_battery／soft_off_charging。
  - 擷取時間預設 3000 ms；OTA「開機自動套用」預設關。
- 新增校正指令：`calibration-set-fit`、`calibration-dump-fit`、`calibration-set-reference`；擷取指令可加 `--reference`。
