# v0.14.2

**修正：「檔案」頁下載時若有一塊讀取失敗，會以每秒 8–10 次的頻率無限重送同一個請求。**

## 為什麼

AC14 更新到 v1.7.4 後，狀態 LED 一直在紅色和藍綠色之間閃。序列埠紀錄顯示，一個開著「檔案」頁的瀏覽器分頁
在 20 秒內送了 186 次 `file_read_chunk`，每次都回 `file_read_failed`。紅色是指令失敗的三連閃，藍綠色是收到和成功的確認閃。

`downloadFileBytes()` 不檢查失敗的回應。失敗的回應沒有 `data` 也沒有 `next_offset`，所以 offset 永遠不會前進；
沒有 `has_more` 時又用「offset < 檔案大小」判斷還有沒有下一塊，結果永遠是「還有」。
最可能的觸發情境：下載途中裝置重開去更新韌體，重開後檔案變了，原本的 offset 已超出檔案結尾。關掉分頁後迴圈就停了。

## 變更

- **下載遇到失敗會停下來**：一塊讀取失敗時，先重新讀一次檔案大小再重試一次。
  - 大小變了（檔案在下載途中被改過）就以 `file_changed` 中止，不把新舊兩個版本拼在一起。
  - 第二次仍然失敗就中止，在頁面上顯示「下載失敗」和原因，進度條也會收起來。以前錯誤被默默吞掉，進度條會一直停著。
- **沒有回應也算失敗**：逾時的回應以 `no_response` 中止，不再當成空資料重試。
- **offset 沒有前進就中止**（`file_read_stalled`），同一類問題不會再變成無限迴圈。
- log 預覽和 App 套件讀取（`readDeviceFile`）使用同一組檢查。`readDeviceFile` 新增行為測試：永遠失敗、逾時、不前進的回應都會停下來。

## 驗證

- Python（483）、frontend（90）測試全數通過；`npm run build` 通過。
- **尚未在瀏覽器與實機上驗證**：下載途中讓裝置重開時，應該顯示「下載失敗: file_changed」或 `file_read_failed`，並且停止送出指令。
