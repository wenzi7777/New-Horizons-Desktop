# v0.14.0

搭配韌體 v1.7.0：裝置設定的 **App 頁籤可以即時看到 app 的輸出**，包括虛擬 OLED、狀態 LED 和外接燈條。
顯示的是裝置自己回報的實際狀態，不是在瀏覽器模擬。

## App 即時輸出

- 設定頁的 App 頁籤和獨立的 Apps 頁都新增 **「即時輸出」區塊**，內容來自新的唯讀指令 `app_view`：
  - **虛擬 OLED**（128×32），下方標示每一行由哪個 slot 畫的。沒有 OLED 的 GCU 板也看得到 app 畫了什麼；
    實體面板不在 app 頁時，會提示目前顯示的是哪一頁。
  - **狀態 LED**：目前的顏色，以及由系統（附上系統狀態）還是哪個 slot 控制。app 要求的顏色被系統狀態壓下時會說明。
  - **外接燈條**：由 app 驅動時顯示每個像素；否則註明正在顯示已設定的預設效果。
  - **衝突提示**：兩個以上的 slot 同時畫同一行 OLED、或同時要求狀態 LED 時，列出哪些 slot 在搶、
    哪個 slot 勝出（編號最小的 slot 優先）。
- 至少一個 app 在執行、且頁面在前景時才會輪詢。間隔取 500 ms 和來回時間兩倍中較大者，經 Hub 時會自然放慢；
  可用「即時預覽」開關關閉。
- 預覽不寫操作日誌，也不會讓按鈕進入忙碌狀態。它跟使用者的操作不會同時送到裝置（Hub 每台裝置一次只轉送一個指令）：
  設定頁的背景輪詢會在使用者操作時略過，使用者操作則等輪詢結束再送出。
- 韌體早於 v1.7.0 時顯示「需要韌體 v1.7.0」，不再輪詢。

## App Studio

- 模擬器的 OLED、LED、燈條元件抽出為共用元件，行為不變。LED 說明補上「實機上系統狀態優先」。

## 裝置與終端機

- 終端機新增 `app-view` 指令；後端指令白名單加入 `app_view`，mock 裝置會回傳會變動的示範資料。

## 驗證

- Python（473）、frontend（85）測試全數通過；`npm run build` 通過。
- **尚未在瀏覽器與實機上驗證**：即時輸出區塊、衝突提示，以及 Hub 模式下的輪詢間隔。
