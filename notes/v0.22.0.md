# v0.22.0

## 更新通道（正式版／測試版）

裝置、Hub、Gateway 都可以選 `stable`（正式版，預設）或 `beta`（測試版）。測試版會先收到實驗性的版本，也會收到每個正式版。

- **裝置設定 → 更新**：新增「更新通道」下拉選單。切到測試版前會先確認並提醒「實驗性、可能不穩定」，選了就立即生效。原本的 Manifest URL 改放在「自訂 manifest URL（進階）」，留空就跟隨通道。Check／Apply 不再自己帶網址，交給裝置依通道決定。
- **Hub 管理 → 更新**：新增同樣的通道切換。
- 從測試版切回正式版不會降級：裝置會停在目前的測試版，畫面提示「正式版追上後會自動回到正式版」。
- 舊版韌體（v1.14.0 之前）沒有通道，會隱藏切換，保留原本的 URL 欄位。
- 後端依每台 Gateway 自己回報的通道告訴它最新版本，測試版永遠不會強制推給正式版的 Gateway。
- 版本比較改為支援 `vX.Y.Z-beta.N`（測試版排在對應正式版之前）。App 的 min_os 與功能門檻只比主版號，所以測試版韌體也能安裝要求對應正式版的 App。
- Terminal：`set-ota-config` 新增 `--channel stable|beta`；沒給 `--manifest-url` 時不再送空字串，避免把裝置的自訂網址清掉。

## 掃描延遲

- **串流診斷**卡新增「掃描開始延遲」：晚開始的次數與比例、最大延遲、最近 5 秒最大延遲、四段分布（<0.5／<2／<5／≥5 ms），以及 ≥250 ms 的暫停次數。這是韌體 v1.14.0 的新指標，以前的 overrun 看不到這種延遲。

## 電池計重新同步不再卡住掃描

- 重新同步期間每秒讀一次狀態。以前讀的是完整的 `status`（約 18 KB，裝置要花約 14 ms 組出來，每秒讓掃描晚一次）；現在改讀新的 `battery_status`（約 1.9 KB、約 2 ms）。舊韌體沒有這個指令時自動改回 `status`。

## 相容性

- 舊韌體、舊 Hub、舊 Gateway 都能照常使用；新功能需要韌體 v1.14.0、Hub v0.9.0、Gateway v0.7.0。

Companion firmware release: **New Horizons OS v1.14.0**.
