# v0.7.0

## NHOS 品牌縮寫

對外顯示的**短標籤**統一縮寫為 NHOS;長文說明、log 與程式註解維持原樣。

- 產生的預設設備名:`New Horizons OS-<UID>` → `NHOS-<UID>`
- 中繼器登錄預設名:`New Horizons Gateway` / `New Horizons Hub` → `NHOS Gateway` / `NHOS Hub`
- 瀏覽器標題、`appSubtitle`、Terminal 就緒訊息與無資料訊息

### 舊設備相容

`_canonical_device_name()` 同時接受新的 `NHOS-` 與舊的 `New Horizons OS-` 前綴,
並一律正規化成新格式。這點很要緊:v1.0.0 之前的韌體會持續回報舊的預設名,若只
認新前綴,那些設備會被誤判成「使用者自訂暱稱」,卡片上就會用原廠名蓋掉使用者
設定的暱稱。`test_device_name_canonicalization` 兩個方向都釘住了。

## 裝置核心層的 Terminal 介面

對應韌體 v1.0.0 的 kernel layer,新增 18 個命令(三語齊全):

- **排程與服務**:`task-list`、`service-list`、`service-restart`
- **診斷**:`crash-log`、`crash-clear`、`dmesg`、`capabilities`
- **設定**:`config-schema`、`config-get`、`config-set`、`set-power-profile`
- **應用**:`app-list`、`app-enable`、`app-disable`、`app-revive`、
  `app-load-rules`、`app-unload-rules`
- **時間**:`set-time`

`file-list` / `file-read-chunk` 新增 `proc` scope,可在非維護模式下讀取即時
核心狀態(例如 `--scope proc --path tasks`)。

## Direct 模式自動授時

ESP-NOW/Direct 模式的設備永遠不會關聯 AP,因此無法透過 NTP 取得時間,所有封包
的 `epochValid` 都是 false。Backend 現在會在設備回報時鐘未同步時,以一般的
`set_time` 控制命令推送牆鐘時間,沿用既有傳輸路徑(Gateway UDP 或經 Hub 中繼),
不新增任何協定。

推送**只在設備明確回報 `clock.synced = false` 時**觸發。v1.0.0 之前的韌體沒有
`set_time` 命令、也不回報 `clock` 區塊,會被視為「狀態未知」而不推送 —— 否則每
台舊設備都會週期性收到註定失敗的命令,而 Hub 在命令 pending 期間會暫停 sensor-data
中繼。`test_clock_push_guard` 釘住這個判斷。
