# v0.9.2

修正裝置 Apps 分頁的無限指令迴圈，並依 Apple 設計語言重新設計所有 App 相關介面。

## 修正：Apps 分頁不停送指令

進入裝置設定的 Apps 分頁後，WebUI 會一直循環送出 `app_list` → `app_list_packages` →
`app_events`，永不停止。

原因：`DeviceSettingsPage` 傳給 `DeviceAppsPanel` 的 `runner` 是每次 render 都重新建立的
inline 函式，而面板的 `refresh()` 依賴它的身分。每一個指令都會讓設定頁重新 render →
產生新的 `runner` → 新的 `refresh()` → effect 再跑一次。`ReadoutView` 的輪詢也以同樣的
方式在每次 render 時重新開始。

兩個元件現在都經由 ref 讀取 `runner`，effect 只會因真正的輸入改變而重跑。

在無頭瀏覽器中實測，Apps 分頁閒置 12 秒：

| | `app_list` | `app_list_packages` | `app_events` |
|---|---|---|---|
| 修正前 | 1052 | 1052 | 1051 |
| 修正後 | 1 | 1 | 1 |

新增 `RunnerIdentityTests`，釘住 `refresh()` 與 `poll()` 的相依陣列都不含 `runner`。

## 重新設計：App 介面

- **App Store**：大標題、搜尋欄、以分類 chip 取代下拉選單；卡片採 App Store 風格
  （圓角方形圖示、兩行摘要、「查看」膠囊）；載入時顯示骨架。
- **App 詳情**：大圖示、資訊條（版本 / 需求版本 / 估計成本 / 節點數 / 大小 / 分類 /
  授權）、權限標籤、可點選的裝置清單。README 以 Markdown 渲染。
- **裝置 Apps**：頂部模式橫幅，進入/退出維護模式集中在一個按鈕；四個槽改為卡片，
  含狀態膠囊與標出峰值的預算條；空槽以虛線顯示，**不再出現沒有意義的「啟用」按鈕**；
  套件、readout、事件改為分組清單；解除安裝改用 app 內的確認對話框，不再用瀏覽器原生
  的 `confirm`。
- **Readout**：脈動的「即時」指示，重新整理與暫停/繼續改為圖示按鈕。
- 尊重 `prefers-reduced-motion` 與 `prefers-contrast`；手機寬度下標題改為堆疊。

README 來自 App Library，屬於不受信任的內容：新的 `Markdown` 元件只產生 React 元素、
不使用 `innerHTML`，且只有絕對的 http(s) 連結可點選。
