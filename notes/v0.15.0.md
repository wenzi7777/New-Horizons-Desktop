# v0.15.0

**板子型號改名：VD-CTL/R → TIA-CTL/R。**

## 為什麼

壓力矩陣的讀出電路是跨阻放大（TIA）：讀取線被運放固定在虛地電位，輸出和感測點的電導成正比。它不是分壓電路，所以產品名改成 TIA-CTL/R。

## 變更

- **畫面上的型號一律顯示 TIA-CTL/R**：Launchpad、Visualization、Device Settings、Terminal 的 I/O 設定視窗。還在跑舊韌體、回報 `VD-CTL/R …` 的裝置也會顯示成 TIA-CTL/R。
- **Wiki**：各板子頁面的標題與內文改成 TIA-CTL/R。網址（`vd-ctl-r-*`）不變，舊連結照常可用。
- **兩種名稱都認得**：從 New Horizons OS v1.8.0 起，韌體回報 `TIA-CTL/R …`。前端和後端比對型號時，把開頭的 VD-CTL/R 視為 TIA-CTL/R。所以不論新舊韌體，板子設定（按鈕、電池、腳位圖、預設 OTA 網址）和 wiki 都對得到同一塊板子。
  - 後端計算感測點數量的地方原本用字串嚴格比對，也改用同一套比對規則。
  - Device Settings 判斷 v1.5.F 的電源說明時，不再寫死型號字串。

## 驗證

- Python（483）、frontend（91）測試全數通過，新增「舊名稱仍對得上」的檢查；`npm run build` 通過。
- **尚未在瀏覽器與實機上驗證**：接上跑 v1.7.5 和 v1.8.0 的裝置，都應顯示 `TIA-CTL/R …`，板子設定也應正確。

## 相容性

- 應先於韌體 v1.8.0 更新 Desktop。較舊的 Desktop 認不出回報 TIA-CTL/R 的裝置，會退回 v1.0.F 的預設設定。
- 不改變任何指令或資料格式。

Companion firmware release: **New Horizons OS v1.8.0**.
