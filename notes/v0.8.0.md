# v0.8.0

新增 **App 商店**。本版只做瀏覽 —— 目錄、詳情、離線快取、套件驗證都到位,
但**還不能安裝到裝置**:安裝需要韌體 v1.1.0 的 `app_install` 指令與多槽註冊表,
屬於後續版本。

## 應用目錄

App 來源是新的 GitHub repo [NHOS-App-Library](https://github.com/wenzi7777/NHOS-App-Library)。
沿用韌體 OTA manifest 既有的作法,從 raw.githubusercontent 取一份 `index.json`,
不走 GitHub Releases API:免 token、免分頁、且套件是幾百 bytes 的 JSON,在 PR 裡
diff 看得懂,而 release asset 是不透明的 blob。

### `app_library.py`

- `fetch_index()` 帶 `If-None-Match`,並在**連不上時回退磁碟快取並標記 `stale`**。
  離線時顯示一份過期目錄,遠比顯示一片空白有用 —— 但 UI 必須說得出它是過期的,
  所以 `stale` 與 `error` 一起回傳,而不是取而代之。
- `validate_package()` 是純函式,檢查 id 規則與 15 字元上限、節點數、後向引用、
  已知 op、事件名長度、套件大小。
  這些檢查與 App-Library 的 CI 重疊是**刻意的**:CI 是作者閘門,告訴作者他的 app
  寫錯了;這裡是防禦閘門,確保即使目錄被手改、過期,或根本不是由該 library 提供,
  畸形的套件也到不了裝置。
- `download_package()` 驗 size 與 sha256,並對 `package.url` 做 **host 白名單**。
  那個 URL 來自一份遠端檔案,對本行程而言就是外部輸入,不能直接拿去 fetch。
- 回傳 `data_hex` 而非 base64,因為 `file_write_chunk` 本來就吃 hex —— 前端不該
  為了送出而重新編碼一次。

### REST

五條 route,全部 admin 限定:`GET /api/app-library/index`、
`GET /api/app-library/apps/<id>`、`POST /api/app-library/apps/<id>/package`、
`POST /api/app-library/import`、`GET /api/app-library/packages/<cache_key>`。

## 商店頁

`/apps` 與 `/apps/:appId`(三語)。卡片網格、分類與關鍵字篩選、詳情頁顯示版本、
作者、授權、需要的 OS 版本、節點數、估算成本與權限,並抓取該 app 的 README。
目錄過期時頁面會明說。

## 分工:後端管目錄,前端管裝置

安裝編排日後會放在**前端**。理由是後端沒有任何 await-result 原語 ——
`publish_command` 在每條 transport 上都是 fire-and-forget,全系統唯一的
request_id↔result 關聯在 `lib/deviceCommand.ts`。把編排放後端等於要重造關聯、
序列化、逾時與取消,是一個新子系統而不是一個新函式;而且分塊進度需要一條後端
目前沒有的 push channel。

## 測試

- `test_app_library.py` —— 防禦閘門的每一種違規各拒一次;sha256 與 size 不符、
  非白名單 host(SSRF)、純 http 各自被拒;離線時回退快取並標記 stale;
  cache key 逃不出快取目錄。另有一條測試直接拿**旁邊 NHOS-App-Library 實際發布的
  套件**過一次防禦閘門,把兩個 repo 綁在一起。
- `test_app_library_api.py` —— 未驗證 401、目錄形狀、未知 app 為 404、
  `/package` 回傳偶數長度 hex 且解碼長度等於 `size`。
- `test_app_store_static.py` —— 路由與 nav 接線、admin 限定、CSS class 存在,
  以及**三本字典的鍵必須一致**。zh-CN 是獨立物件而非 en 的展開,所以漏翻一個鍵
  在執行期是靜默失效的;這個 repo 先前完全沒有這項檢查。

## 已知限制

`NHOS-App-Library` 尚未推上 GitHub,在推送之前商店頁會顯示無法載入目錄。
可用 `NEWHORIZONS_APP_LIBRARY_URL` 指向其他位置。
