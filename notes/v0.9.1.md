# v0.9.1

支援 **readout** 套件：裝在裝置上、由 Desktop 渲染的宣告式介面。需要韌體 **v1.2.0**。

## 它是什麼

v1.1.0 的套件只有 flow 圖，在裝置上每幀執行。但「任務管理器」這類東西不該在裝置上
執行 —— 它只是把裝置已經量到的數字讀出來，而資料流圖也渲染不出 UI。

readout 列出要輪詢哪些裝置指令、要畫哪些元件。韌體不解讀它的內容,只存下來與回報。

## 它仍然裝在裝置上

只裝進 Desktop 的話,「這台裝置裝了什麼」就只存在於當初安裝它的那台電腦裡。
**裝置才是事實來源**,所以 readout 照樣進 registry、照樣跟著裝置走,只是不佔槽、
不耗預算、不被派送。

因此 `DeviceAppsPanel` 開啟一個 readout 時是**從裝置讀回套件**(`file_read_*`),
不是從目錄拉 —— 這對側載的套件、或目錄連不上的時候一樣有效。

## 安全性

readout 是在**操作者的瀏覽器裡**渲染的,所以「宣告式、不帶程式碼」在這裡比在裝置端
更要緊。可輪詢的指令是白名單且**全部唯讀**;渲染器不做任何 `eval` / `new Function` /
`innerHTML`,套件的欄位名只用來索引結果,永遠不會變成程式碼。

白名單在三處各驗一次:App Library 的 CI、Desktop 後端、以及瀏覽器端的渲染器 ——
因為套件可能來自被手改的目錄。

## System Monitor

第一個 readout。排程器負載、掃描速率與錯過的截止期限、記憶體(含**最大連續可用
區塊**,碎片化指標)、以及任務 / App / 服務三張表,任務表按 CPU 排序並附長條。

**只顯示真實可量測的東西。** 裝置沒有每任務 RAM 歸屬,也沒有電流感測器,所以刻意
沒有那兩欄 —— 看起來像 macOS 但其實是編的數字,比沒有那一欄更糟。

實機上它立刻顯示出兩件先前看不到的事:`imu` 任務佔 24.6% CPU、每次 5.08ms;
heap 空閒 131.1 KB 但最大連續區塊只有 48.0 KB。
