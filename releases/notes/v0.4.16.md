# New Horizons Desktop v0.4.16

## Changes

### Backend support for real device epoch timestamps (protocol v4)

- Devices on firmware v0.11.3+ NTP-sync their clock and embed a real epoch
  millisecond timestamp directly in the UDP packet header, instead of
  `millis()`-since-boot. This required widening the packet header's timestamp
  field from 4 to 8 bytes (20 → 24-byte header), a new `NHO/Arduino/1`
  protocol version (v4), and a new flag bit marking whether the timestamp is
  a genuine synced value.
- `packet_parser.py` and `arduino_protocol.py` now branch on packet version so
  both v3 (legacy, uptime-based) and v4 (epoch-based) devices parse and
  classify correctly — this is additive, not a breaking cutover for devices
  still on older firmware.
- CSV export now prefers the device's real `device_epoch_ms` when present,
  instead of always falling back to the backend's own receipt-time wall
  clock — this fixes CSV timestamps being wrong for any sample that was
  buffered on-device (stream-buffer queue) and sent late.
- Requires a matching New-Horizons-Gateway update landing alongside this —
  the Gateway hardcodes packet version/header length for its own routing, so
  an unupgraded Gateway will not recognize v4 packets from updated devices.

## Verification

- `npm run build` — passes.
- Backend packet-parsing/classification logic smoke-tested standalone for
  v3 (legacy), v4-synced, v4-not-yet-synced, and truncated-packet cases.
- Not yet exercised end-to-end against a real v0.11.3+ device — the firmware
  side of this feature is build-verified only, not flash-tested on hardware.
